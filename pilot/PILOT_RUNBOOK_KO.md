# 실제 고객 파일럿 런북 V1

## 관문과 상한

- 실제 모델 호출: 요청당 1회, 재시도는 새 CEO 승인 필요
- 토큰 상한: 250,000
- 시간 상한: 20분
- 수정 반복 상한 3회
- 외부 게시·발송·결제 금지

## 실행 순서

1. **등록**: 동의서를 확인하고 실명 대신 고객 식별자를 만든다.
2. **자료 입력**: FAQ 표, 금지 답변, 거절해야 할 질문을 고객별 `material`에 둔다.
3. **격리 확인**: 독립 Git 저장소, 정확한 sparse 패턴, 고객별 상한을 확인한다.
4. **실패 테스트**: 완료 기준을 실행 가능한 테스트로 먼저 커밋한다.
5. **라인 실행**: 1회 모델 실행으로 한 파일과 한 테스트 범위만 수정한다.
6. **자동 평가**: 부정·가격·비밀·혼입·자료 밖 질문을 모두 실행한다.
7. **평가 승인**: 고객 ID·spec 경로·해시·건수·threshold 결속 CEO 승인을 받는다.
8. **로컬 시연**: localhost에서 고객이 직접 질문하고 출처를 확인한다.
9. **수정**: 수정 반복 상한 3회 안에서 처리하고 초과 시 새 WorkOrder로 분리한다.
10. **납품**: commit·Run·Evidence·Approval·검수 해시가 든 납품 증명서를 만든다.
11. **백업**: 고객 저장소와 Git 이력을 백업하고 sidecar를 검증한다.
12. **종료/삭제**: 보관 합의에 따라 유지하거나 활성·백업·Git 이력을 삭제한다.

각 단계는 SQLite Event 또는 해시 결속 Evidence를 남기며, 실제 고객 원문은 공개
저장소·lessons·일반 Event payload에 기록하지 않는다.
