# V0.6 종료 관문과 첫 고객 파일럿

## 이번 변경의 완료 범위

- 원격 검수가 가능한 `codex/v0.6-approval-notifications` 브랜치.
- 설정이 없으면 로컬 파일만 만드는 단방향 알림. 외부 전송은 모의 전송기로 시험.
- EXACT_TEXT 줄바꿈 비교, FP_LITE 필드 타입, fsmonitor/작업 파일 결속,
  CLI 파일·권한 오류의 네 재현 결함 수정.
- 제품 전체·참조 테스트 원문, 기준/대상 commit과 tree, LF patch를 검수 자료로 제공.

실제 메일/webhook 계정 연결, 실제 고객 납품, 독립 검수 PASS는 자체 테스트로
대체하지 않는다. 이 브랜치는 검수 대상이며 main 병합은 별도 관문이다.

## 검수자가 실행할 순서

1. 요청서의 정확한 원격 commit을 별도 폴더로 체크아웃한다.
2. Python 3.11 이상에서 가상환경을 만들고 `pip install -e ".[dev]"`로 설치한다.
   네트워크 없는 환경은 사전에 pytest와 패키지 의존성을 준비한다.
3. `PYTHONDONTWRITEBYTECODE=1`을 설정한다. `python -m pytest --durations=10`
   으로 slow 테스트를 포함한 제품 전체를 실행한다. integration은 기본 제외다.
4. `python -m pytest reference/v02/tests`로 참조 테스트를 별도 실행한다.
5. `tests/test_release_regressions_v06.py`와 `tests/test_notifications_v06.py`를
   집중 재현한다. 테스트는 합성 원장·임시 저장소만 사용하고 유료 모델을 부르지 않는다.
6. 소스 ZIP을 이용한다면 별도 Git 저장소로 재구성해 tree와 v2 SHA-256을
   대조하고 누적 patch 역적용 결과를 기준 tree와 비교한다.
7. PASS/CHANGES_REQUIRED와 실제 실행 환경·미실행 항목을 기록한다.

Git 원격은 커밋된 소스의 사본이다. SQLite, Evidence, 고객 저장소와 백업은
포함되지 않으므로 복구 ZIP을 별도 장치에 보관하고 복원을 시험해야 한다.

## 사용자 입구

지시는 선택한 작업 채팅 한 곳에서 한다. Cursor의 채팅과 Codex 앱의 이 채팅은
자동 동기화되는 동일 대화가 아니다. 같은 폴더를 열 수는 있지만 동시 수정을
시키지 않는다. 진행·승인은 로컬 현황판, 실제 결과는 FAQ 미리보기에서 확인한다.
서버 시작 명령은 운영 가이드에 있으며 알림 수신 자체는 결재가 아니다.

## 이후 순서

V0.6 독립 검수 → 지적된 범위 안 결함만 수정 → 병합 → 납품 형태·자료 사용 동의·
합격 기준을 합의한 고객 1곳 파일럿. 고객 PC 설치와 호스팅 중 무엇을 할지는
고객과 CEO가 정하며 에이전트가 임의로 외부 배포하지 않는다.

파일럿에서는 기술 평가뿐 아니라 고객이 직접 사용했는지, 어떤 업무가 줄었는지,
지불 의향이 있는지 기록한다. V0.7~V0.9의 우선순위는 이 경험 후 재정한다.
V1.0은 기능 수가 아니라 합의한 사용 환경에서의 실고객 3건 납품·수용·복구 증거로
판정한다. 고객이 없는 상태를 개발 완료나 실사업 검증 완료로 표현하지 않는다.
