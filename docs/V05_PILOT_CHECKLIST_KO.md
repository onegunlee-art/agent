# V0.5 실제 고객 파일럿 체크리스트

## 시작 전 동의

- [ ] 고객에게 로컬 시험 목적, 처리 자료, 보관 위치와 보관 기간을 설명했다.
- [ ] 고객이 제공 권한을 가진 FAQ와 금지 답변 목록만 받았다.
- [ ] 모델 공급자·도구에 전달될 수 있는 범위와 사람이 최종 승인한다는 점에 동의했다.
- [ ] 고객 실명 대신 내부 고객 식별자를 정했고 연락 담당자와 비상 연락 방법을 기록했다.
- [ ] 발송·게시·결제 권한은 실행자에게 주지 않는다고 확인했다.
- [ ] 납품 형태를 고객과 합의했다: 로컬 시연만인지, 고객 PC 설치와 인수시험까지인지
  구분한다. 호스팅은 별도 운영·보안 범위로 합의하기 전 포함하지 않는다.
- [ ] 결정적 FAQ 검색 제품이며 매 질문에 LLM이 답을 생성하는 제품이 아님을 설명했다.

## 실행과 확인

- [ ] `client init`으로 OneDrive 및 공개 저장소 밖에 고객별 독립 Git 저장소를 만들었다.
- [ ] 고객 저장소의 Git 최상위 경로가 정확히 `clients/<id>`이며 다른 고객 저장소와
  객체를 공유하지 않는지 확인했다.
- [ ] 고객별 토큰·비용 상한과 sparse 경로 네 개를 확인했다.
- [ ] 다른 고객 표식이 `critical_forbidden`에 포함된 평가를 실행했다.
- [ ] 부정 질문·가격 추측·비밀정보·타 고객 혼입·자료 밖 질문을 직접 시험했다.
- [ ] 고객에게 localhost 미리보기를 보여주고 서면 승인 전 외부 공개하지 않았다.
- [ ] 고객이 합의한 사용 환경에서 직접 시험했다. 제작자 PC 시연만으로 납품 완료를
  선언하지 않았다. 반복 질문 감소 등 가치와 실제 지불 의향을 고객에게 확인했다.

## 롤백과 장애 연락

- [ ] 변경 전 고객 백업 ZIP과 sidecar를 만들고 `client verify-backup`을 통과시켰다.
- [ ] 장애 시 서버를 중지하고 마지막 검증 백업을 빈 경로에 복원하는 담당자를 정했다.
- [ ] 잘못된 답변, 데이터 노출, 비용 초과가 발생하면 즉시 실행 중지 → CEO → 고객
  담당자 순으로 연락한다.
- [ ] 사고 시각, 영향 질문, Run ID, 조치와 재개 승인을 Event로 남긴다.

## 종료·삭제

- [ ] 고객에게 결과와 남은 한계를 설명하고 납품 또는 종료 승인을 받았다.
- [ ] 보관 기간 종료나 삭제 요청 시 `client delete`를 정확한 고객 ID 확인과 함께 실행했다.
- [ ] 고객 저장소 전체(`.git` 이력 포함)와 고객별 백업이 사라졌는지 확인했다.
- [ ] 삭제 인증서의 active/backup/git-history 범위가 모두 제거됨으로 표시되고,
  인증서 SHA-256과 Event가 남았는지 확인했다.

파일럿 시작 관문은 V0.5 완전 검수 PASS와 CEO 승인이다. 이 체크리스트 자체는 고객
동의를 대신하지 않는다.
